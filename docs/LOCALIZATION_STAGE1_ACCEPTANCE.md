# 多语言与共享设计系统：第一阶段

日期：2026-10-24。交付范围：本地源码；未打包发布桌面安装包。

## 已实现

- 保留现有 `system | zhCn | en` 设置格式，集中解析为 `en | zh-CN`。系统语言按优先顺序匹配；支持简体脚本及中国/新加坡地区，不将繁体中文标记为已支持。系统语言变更事件实时更新跟随系统的界面。
- `src/i18n/` 提供 Context、类型化消息 key 和参数、英文回退、数字/日期格式化及复数选择。HTML `lang` 使用真正生效的语言。
- 设置页全部 14 个分类的标签、说明、操作、确认提示、搜索、更新流程和能力矩阵已接入词典。分类搜索同时包含英文名称、当前语言名称和中文领域别名；快捷键支持中英文搜索。
- 主导航的数据库/查询/变更切换、搜索入口、工具提示、命令面板、模型视图入口、侧栏按钮、通知入口和更新横幅已适配。通知中的已发生事件文本保留发生时的语言，新事件使用当前语言。
- 语言保存成功后生效，失败时显示本地化错误概述并保留旧偏好。保存期间禁用语言选择，避免连续请求覆盖。
- 语言变化不重建设置页。对服务配置采用内容变化检测，避免重新读取设置时用新对象覆盖未保存 AI/云配置草稿。表 AI 会话不再因语言变化而重建，保留问题、回答和正在进行的请求；其现有双语内容仍待后续整体迁移到词典。
- 已将表单控件与样式迁入 `design-system/forms.tsx`、`forms.css`，旧导入路径兼容。设置按钮采用共享 `Button`，集中管理变体、尺寸与忙碌状态；增加中文字体回退、焦点、阴影、遮罩和层级 token。
- 增加开发专用 `/design-system-preview.html`；设置预览支持 `language=en|zh-CN`。

## 开发约定

```tsx
const { t, formatDate, plural } = useI18n();
const label = t("settings.language");
const countLabel = t(
  plural(count) === "one" ? "settings.sources.count.one" : "settings.sources.count.other",
  { count },
);
const timestamp = formatDate(isoTimestamp, dateTimePreference);
```

在 `i18n/messages/en.ts` 和 `zh-CN.ts` 同时增加稳定 key；类型检查约束 key 和所需参数，测试校验词典和占位符的一致性。不要翻译 SQL、用户文本、数据库标识符或接口枚举。不要改变持久化设置枚举来表示 UI 文案。

渲染使用响应式 `t`。数据加载 effect 或长生命周期异步回调若仅需要生成反馈，可使用 `useEventTranslator(t)`，避免为更换语言重新执行网络请求或加载工作区；此接口不能用于替代渲染时的响应式翻译。设置页自身通过 Provider 保证独立预览和直接渲染测试也使用相同规则。

能力说明仍由 `platform/capabilities.ts` 定义支持边界；`i18n/capabilities.ts` 将稳定功能 ID 映射到消息 key。测试逐项比对英文词典与原声明，防止支持范围修改后翻译悄悄过期。迁移范围内的静态 JSX 文案有增量防回退检查，技术名称和示例路径有明确例外。

## 后续范围

对象树、连接编辑、画布业务面板、查询工作区、历史详情等尚未全面接入词典。本轮只覆盖主导航入口，不代表它们打开的所有业务页面都已中文化。

后端错误详情、策略说明、发行说明正文、审计标识和供应商返回内容保留原文；稳定错误码的完整映射属于后续边界层改造。新增语言时需补词典、解析规则及验收，不应继续在业务组件添加语言分支。
