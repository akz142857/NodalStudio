## 已实现功能与入口

- [x] 在 Desktop 单表 AI 回答的每条业务推测旁提供 **Generate annotation draft**。草稿从这一条已校验的解释提取，保留限定语、原证据、未知项及模型来源；不复制整段回答，也不再次联网。
- [x] 草稿显示原描述、新描述、来源与原始依据；允许编辑，必须点击 **Confirm this description** 才保存。准备草稿、查看依据及取消均不写入注解。
- [x] 选表 → **Semantics** → **Knowledge review on this device**，可复核当前描述，也可展开其他待复核描述。对象不存在或不能可靠映射时仅展示原文和原因，不自动附着到其他对象。
- [x] 保存时原子校验目标、相关结构、所引用团队说明与原注解版本，只更新描述及本机确认记录，保留 tags、owner、isCore。并发修改拒绝覆盖；错误保留编辑内容，重试使用同一草稿 ID。
- [x] 已确认且依据仍有效的说明参与业务检索，模型上下文单独标记为 `teamStatement`。旧数据、外部首次导入、待复核和不可用说明均不参与复用。
- [x] 描述或相关依据变化后持久降级；改回旧文本、恢复同名对象、重复导入、整体指纹重新匹配都不能自动恢复确认。
- [x] Git、云接收/合并、旧数据和便携模型备份沿用同一存储校验规则，未扩大现有共享字段。

离线或 AI 关闭时仍可人工复核本机结构与描述。Web Viewer 没有写入/确认能力；共享文本明确不携带本机复核证明。历史快照与 DDL 临时模型不启用此确认通路。

## 交互流程

1. 加载 Desktop 当前来源的最新快照，在单表 AI 面板按既有发送范围预览并执行解释。
2. 选择一条推测，生成独立草稿；对照已保存文本、原证据和未确定事项，编辑简短描述。
3. 显式确认。成功后更新语义和本地检索；团队说明仍是人工确认的业务解释，不升级为数据库结构事实。
4. 从 Git、云或备份收到缺少本机依据的文本后，在 Semantics 中查看待复核原因、导入文本、当前结构及可用的旧确认依据。
5. 可以保留待复核，也可编辑后再次确认。失效描述保留原文；只有新确认成功才恢复复用。

草稿最多同时保留 16 份，五分钟后过期。模型草稿沿用源解释的截止时间，不因再次生成草稿延长源回答寿命。取消、目标/来源/快照/有效语义切换隔离晚到结果；确认前还会在后端重新校验。已在有效期内提交的保存继续等待结果并刷新状态，不因响应晚于倒计时而丢失保存反馈。

## 本机状态与跨机器规则

阶段三通过 SQLite schema 4 引入独立的 `annotation_confirmations` 表；第二轮修复升级到 schema 5，以支持结构回到历史版本时记录新的采集（迁移规则见后文）。正文仍使用现有 `ObjectAnnotation`；本机记录保存最终文本摘要、确认 ID/时间、目标、快照标识、相关依据摘要、连接身份摘要及来源。正文与确认在同一事务写入，描述与有效性也成对读取。

| 接收或修改场景 | 本机结果 | 是否可复用 |
|---|---|---|
| 旧记录或首次收到外部描述，没有本机确认依据 | 待复核 | 否 |
| 本机已有效，同文再次导入，依据未变 | 保留本机原确认 ID 与依据 | 是 |
| 本机已待复核，同文再次导入 | 继续待复核 | 否 |
| 手动、Git、云合并或备份恢复改变描述 | 待复核，不能继承旧文本确认 | 否 |
| 相关字段、约束、结构注释或依赖的逻辑关系变化 | 待复核；保留旧确认以供比较 | 否 |
| 成功更换连接的 host、port、database、数据库类型或 username | 待复核；同构表也不能继承旧库说明 | 否 |
| 删除历史但保留语义；便携恢复导致依据失效 | 在修改事务中持久失效，不依赖中间读取 | 否 |
| 引用的团队说明变化或失效 | 依赖说明级联待复核 | 否 |
| 目标删除或无法可靠映射 | 不可用；同名恢复后仍需复核 | 否 |
| 用户针对当前文本与依据重新确认 | 建立新的本机确认记录 | 是 |

依据采用“连接参数身份 + 数据库名称/类型 + 相关表的完整结构 + 依赖逻辑关系 + 引用团队说明版本”的摘要。无关表变化、相同结构重新采集、仅同步时间戳变化不撤销有效确认。相关表内的任何结构/注释变化会保守地要求复核，不做字段级的精细依赖推断。逻辑关系摘要包含端点映射、基数和状态，忽略不参与解释的自由文本及同步时间。关系先改后改回也不恢复旧确认。

Git 文档、云 bundle、同步事件与便携模型备份继续只共享既有注解正文等允许字段，不导出本机确认记录或 AI 原始依据。包指纹和更新时间不作为逐条有效证明。这里的备份规则指便携模型导入；直接复制整个本机 SQLite 文件不是本次跨机器确认机制的传输入口。

## 复用与 AI 发送边界

- 仅当前来源的 `confirmed` 说明可参与本地业务召回，并显示 **Confirmed team statement** 命中理由；关闭 `includeConfirmedSemantics` 后停用这类复用。
- 解释、候选排序和路径解释继续使用阶段一/二的发送白名单。只有说明所属表及其全部结构依据表都已纳入实际请求，才追加该团队说明；不会通过说明转述超范围表。省略时保留覆盖提示。
- 团队说明单独列示，包含确认身份和文本摘要，能够定位到表/字段；不混入结构事实。预算仍约束实际上下文与最终 HTTP body。
- 旧 `changeSet` / `domain` 解释入口不复用团队说明：这些入口没有逐条依据范围预览，不能将已确认记录简化为正文后发送。新单表解释、候选排序和路径解释仍执行完整依据范围校验。
- 问题独立扩词不发送团队说明。草稿提取与人工复核不调用模型，也不发送新增元数据。
- 正文/依据/语义资格变化会改变后端预览签名及前端任务身份，旧预览、重试、回答和草稿不能继续复用旧依据。
- 完成回答与取消共享同一锁顺序；取消不能落在“移除运行任务 → 缓存回答”之间留下旧草稿来源。

- 前端草稿对照编辑、必须显式确认、保存失败重试、目标切换后的晚到草稿、错误目标拒绝、挂起后过期、保存中截止时间到达；确认语义的本地召回与来源隔离。
- SQLite 乐观版本校验、属性保留、重复确认、文本改后改回、相关/无关采集变化、对象删除再出现、语义依赖级联和循环拒绝、逻辑关系时间戳与结构变化的区别。
- 两份互相隔离的 SQLite 存储模拟 A/B，分别走实际 Git 导入和云接收函数：首次接收、同文重导、唯一约束删除后包指纹匹配、改文合并、再次确认和往返接收；另测便携备份缺证明及变文恢复。
- 假提供方实际 HTTP body：未确认文本不发送、开关关闭排除当前有效文本、白名单排除无关信息、确认文本变更使旧任务失效；核心上下文覆盖说明的全部依据必须在发送范围内。

### 快照迁移与兼容性

本机 SQLite 升至 **schema 5**，去除全历史 `(source_id, fingerprint)` 唯一约束；去重只比较连续采集的当前模型。旧快照的 ID、捕获时间、正文及变更引用保持不变，返回历史结构会新增采集，避免把中间结构继续当作当前模型。同步事件以采集 ID 去重，使 A→B→A 的第二个 A 也有独立事件。

文件数据库升级前沿用自动备份（v4 对应 `*.pre-v4.bak`）；表迁移在事务内完成并检查外键，错误回滚。旧版程序会因 schema 版本高于支持范围而拒绝直接读取新版数据库。便携备份的字段格式不变，新版可保存和恢复重复指纹但不同 ID 的历史。测试仅使用内存或临时 SQLite 文件，没有启动真实用户数据库的迁移。
