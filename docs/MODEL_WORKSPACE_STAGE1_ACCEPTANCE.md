## 阶段 0：行为契约与基线

基线代码为本轮修改前的 `c36a85f`。代码阅读确认：保存视图只存根表/深度，视图排版临时；新增节点可能导致未固定旧节点重排；普通历史图可覆盖来源共用布局。基线是可复现的行为差异，不是用户效率或帧率数据。

| 对象/操作 | 本轮确定的行为 |
| --- | --- |
| 业务域 | 业务归属信息；按域查看仍是临时布局 |
| 新保存视图 | 明确成员，使用现有 depth 0 定义；初始成员可以来自多选，也可在确认面板调整 |
| 旧保存视图 | 根表与关系层数原样保留；编辑明确提示旧语义；新增独立布局，不静默改写为固定成员 |
| 搜索、聚焦 | 临时探索，不覆盖完整模型或保存视图布局 |
| 刷新 | 新增表进入完整模型，但不自动加入明确成员视图；旧坐标、尺寸、固定状态保留 |
| 视图管理 | 名称/成员可编辑，可复制、删除；删除视图只移除该本地视图和布局，保留注释和项目关系 |
| 历史 | 普通历史图和比较图均临时；明确显示历史提示及返回最新模型入口 |
| 恢复 | 完整图和每个视图分别保存；最后打开的视图为本机偏好；选择状态和撤销栈不跨重启 |
| 共享 | 不新增个人视角或每视图布局的云/Git 同步；已有便携备份可包含布局 |

可重复的 PostgreSQL 样例在 [S0](../Scripts/fixtures/model-workspace/s0.sql) 与 [S1](../Scripts/fixtures/model-workspace/s1.sql)。S0 为 30 张合成表（含订单、支付、履约等 7 张业务样例和 23 张辅助表）；S1 新增 refunds 并在无关辅助表增加字段。脚本只用于一次性测试数据库，不能对真实项目执行。

形成性用户观察脚本：定位订单/支付 → 多选保存视图 → 调整成员、位置、固定和视角 → 次日重开 → 应用 S1 后刷新 → 观察是否需要重新整理 → 查看历史、临时排版、返回。记录正确率、耗时、重复整理动作与误判原因。另以自动化覆盖来源同名、复合键/跨 schema 现有图模型、缺失成员、旧布局、保存失败及晚到响应。

**真实目标用户的约 5 人观察、任务计时和行业对照尚未进行。** 本轮完成阶段 0 的工程行为契约、合成基线与观察脚本，没有招募用户，也不将开发者自测冒充需求验证。没有新做大图硬件帧率测量；现有大图回归纳入前端全量测试。

## 阶段 1：实现

- 画布新增 View 工具栏：从多选创建、明确成员确认、名称/成员编辑、复制、删除。缺失成员保留并标注 unavailable；新增对象需显式加入。
- 视图及初始布局在同一 SQLite 事务保存；更新拒绝跨来源 UUID 占用。删除按来源隔离，原子删除对应布局，其他视图及完整图不受影响。
- 沿用 `canvas_layouts(source_id, layout_key)`，按视图 UUID 保存位置、尺寸、固定及 viewport；读取所有本地视图布局。旧 JSON 无 viewport 时仍可读取，无清库或破坏式迁移。
- 完整图和视图恢复不完整时，只向布局 Worker 提交新节点，并将旧节点作为障碍；保留旧节点原固定状态。失败时旧位置仍在，可重试。
- 保存队列继续按序写入，失败保留内存结果；桌面浏览器缓存不替代 SQLite 保存。视角自动恢复不触发保存，用户平移/缩放与控制按钮的视角修改可保存。
- 同来源刷新保持当前视图；历史图不向当前布局写入。App 限制历史写入，当前界面的保存请求携带快照 ID，后端拒绝过期快照；返回最新模型恢复原工作区。

## Review 与修复

本轮为实现者独立复查、自动化回归和原生交互验收，未调用额外 reviewer 代理。

| 发现 | 修复与证据 |
| --- | --- |
| 视图编辑浮层被下方工具栏盖住，名称输入区不可见 | 修正层级及控件样式；原生创建、编辑、复制均实际完成 |
| 增量布局 Worker 失败时，仅固定旧节点能留在原位 | 等待和失败期间保留全部有效旧节点；失败重试专门回归 |
| 用户通过 Zoom 控制按钮调整视角不属于指针移动事件 | 标记明确的控件操作，保存结束后的视角；自动恢复仍不写回；专门回归 |
| 同一快照 ID 从历史预览返回当前模型时，临时排版可能残留 | 将临时浏览状态纳入布局作用域；新增同 ID 历史排版、返回恢复且不写回的回归 |
| 切换来源后旧视图保存返回可能影响新来源界面 | 使用当前语义会话和来源校验；旧回调不能改变新工作区 |
| 新视图创建和布局分两次保存可能产生半完成记录 | 合为同一事务；故意传入不同来源布局，验证整体回滚 |
| 旧视图和新视图容易混淆 | depth 0 明确成员；旧 depth > 0 标明关系层数，编辑保持原语义 |

复查重点还包括：新视图 UUID/来源隔离、删除后晚到布局写入、保存队列、历史和比较边界、缺失成员保留、云/Git 范围、升级 JSON 兼容和导出未扩权。

## 已知边界

- 退出搜索/聚焦恢复所属视图；全局 schema 定位仍会退出局部视图，可从 View 下拉重新打开。没有新增通用前进/后退导航栈。
- 编辑或移除成员不代表删除数据库对象；缺失成员可见、可保留。完整的关系/说明统一变更复核属于阶段 2，本轮未实现。
- 旧表新增字段可能增高卡片，保留坐标优先；不会为了自动避让而移动所有旧表。用户可显式排版。
- 每视图布局和最后视图偏好是本机能力；不等同于多设备实时画布。
- 没有开展真实用户效率/留存实验，没有把测试通过数量作为市场验证。

本轮不改变版本号，不创建发布标签，不部署正式安装包。
