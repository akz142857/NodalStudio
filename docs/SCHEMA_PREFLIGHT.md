# 结构预检

从顶部 **Structure preflight** 或命令面板 **Open structure preflight** 打开。桌面与 Web 对当前已加载快照使用同一套规则，不需要数据库连接。检查整个快照，不受 Diagram 搜索、业务域、保存视图影响；比较图的历史删除对象、逻辑关系和推断候选不进入检查。

界面展示数据库方言、服务器版本、采集时间、指纹、对象数量、耗时和规则覆盖。结果分为设计建议、疑似问题、信息不足和可选风格提示；每项包含规则 ID、对象、采集依据、解释和建议。可按规则、结果分类或文字筛选，每次展示 100 项，并能继续加载。无结果只表示启用规则未产生提示，不表示数据库已验证合法。

**Locate table** 返回 Database，清除图形搜索和局部视图并聚焦对应表；外键结果也能定位已采集的目标表。**Close preflight** 返回打开前的工作区模式。快照切换重新计算，显示新快照身份，不沿用旧结果。

## 首版规则与覆盖

| 规则 | 适用范围 | 结果与边界 |
|---|---|---|
| `table-primary-key` | 普通表、分区表 | 缺少 PK 是设计建议；外部表跳过，视图不进入表检查 |
| `key-references` | 已采集 PK、物理 FK | 空列表、重复字段、两侧字段数量不同或字段不存在：疑似快照不一致。目标表未采集：信息不足，可能属于采集范围之外 |
| `postgres-fk-types` | PostgreSQL 物理 FK 的逐对字段 | 已知 `pg_catalog` 类型身份相同不产生提示；同类型族但类型不同、域/自定义/其他未知类型：信息不足，需要运算符/转换等目录信息。已知类型族不同：标记差异供复核，不断言约束非法 |
| `mysql-fk-types` | MySQL 物理 FK 的逐对字段 | 整数大小/符号、DECIMAL 精度/小数位/符号不同：疑似问题，整数显示宽度忽略。字符类型：缺字符集与排序规则，信息不足，长度差异本身不算错误。其余类型或缺格式信息：信息不足 |
| `name-spaces` | 表名和字段名，默认关闭 | 空白字符是可选风格提示；合法引号标识符不判错，不执行重命名 |

每条规则单独显示 Checked available metadata、Partial 或 Skipped，以及已检查、信息不完整、排除数量和限制。计数单位随规则变化：PK 存在性按表，引用按 PK/FK，类型按字段对（端点缺失时按无法检查的 FK），命名按表名/字段名。另一方言的类型规则会标为不适用。视图数量单列，FK 索引覆盖暂不检查。

已检查的类型身份不代表完整兼容性。PostgreSQL 的跨类型运算符、转换、域、排序规则及约束验证状态未采集；MySQL 的字符集、排序规则、存储引擎及版本特定限制未采集。已经存在的物理约束也不能仅凭类型文本差异断言非法。

规则参考官方资料：[PostgreSQL 外键约束](https://www.postgresql.org/docs/current/ddl-constraints.html)、[PostgreSQL 约束目录及比较运算符](https://www.postgresql.org/docs/17/catalog-pg-constraint.html)、[MySQL 外键类型要求](https://dev.mysql.com/doc/refman/8.0/en/create-table-foreign-keys.html)。当前实现仅检查已有模型允许观察的部分，未完整复刻服务器约束验证器。

## 忽略与本地保存

**Ignore with a reason** 要求填写非空理由（最多 500 字符）。默认隐藏已忽略项，勾选 **Show ignored findings** 可查看理由并 **Restore finding**。忽略不改变检查覆盖，也不删除结果或修改数据库。

理由只保存在本机当前应用/浏览器的 localStorage，以来源 ID + 快照指纹隔离。相同来源、相同指纹重新采集可复用；换来源/结构后不会套用旧理由。结果依据或分类改变时，旧理由不会自动隐藏新结果。理由不进入 SQLite 语义模型、Git 导出、云同步或分享包，不是团队审计记录。

保存失败会保留会话理由、显示错误并提供重试。损坏的旧记录不会阻止预检。清理浏览器/应用本地存储会清除这些理由。

## 实现与验证

`src/preflight/schema-preflight.ts` 为与 React 分离的纯计算模块，输入现有不可变快照，输出规则结果和覆盖；`SchemaPreflightPanel` 负责运行状态、筛选、详情和定位；`preflight-reviews.ts` 管理本地理由。依据评估 §8.3 的修订边界，首版没有新建 Rust crate/插件注册框架：已有元数据可直接在桌面与 Web 共用规则，无需新增 IPC 或云端接口。

重新检查只重新计算当前快照；不刷新数据库，不读取行数据，不运行查询、DDL 或修复 SQL。首版在下一帧开始同步计算，并展示耗时；不宣称后台线程处理。测试覆盖 500 表/5,000 字段及结果分批显示，但不是任意规模性能保证。

新增 50 项规则、理由存储、组件和 App 集成测试，覆盖复合 FK、跨 schema/含点名称、类型差异与信息缺失、空模型、命名选项、来源/指纹隔离、依据变化、保存失败重试、筛选分页及 Web 无数据库刷新/语义写入。实际浏览器验证使用合成元数据，不依赖真实数据库。生产构建、类型检查和 ESLint 与完整前端测试一并验证。
