## 1. 结论与 r2 变化

保留现有桌面一次性买断，新增独立、可选的 Nodal Cloud 订阅。方向不变，r2 调整的是“先验证什么、先卖什么、做多重”：

| 变化 | r1 | r2 |
| --- | --- | --- |
| 进入实施的门槛 | 只有成本/毛利门槛 | P0 增加需求验证与 go/no-go 决定（§7） |
| 首发价值主线 | 个人跨设备同步 → 在线编辑 → AI → Team | **分享给非工程角色 + 评论 + 托管 AI** 先行，同步作为支撑能力（§3） |
| 首发套餐 | Cloud、Cloud AI 两档付费，无免费入口 | 免费账号 + **一个**付费套餐 + 试用（§6） |
| 渠道 | 只写 MAS IAP 与网页收款 | 覆盖 GitHub Community、Developer ID DMG、Windows、MAS、网页与自编译（§5） |
| 技术方案 | 按成熟多租户 SaaS 设计 | 先用最小正确机制，Team 所需机制后置并保留升级路径（技术设计 §0） |
| 工期 | P1–P4 原估 50–70 人日，标注需重估 | 重估为个人付费闭环约 75–110 人日，Team 另计（§13） |

核心定位：**桌面负责安全连接数据库与本地工作；云端负责让不装桌面、不用 Git 的人也能看懂、评论和询问数据库知识。**

## 2. 产品边界

以下边界沿用 r1，作为所有阶段的约束：

- 买断权益与云订阅权益独立。订阅到期、云端故障或退出账号，不影响已购买的本地功能。
- 现有 Git 工作区（`.nodalstudio/`）在所有渠道继续免费可用，云服务不限制、不降级 Git 工作流。
- 在线版可独立注册使用，不要求先购买 Mac 应用；使用 MAS 桌面版仍按现行方式购买应用。
- 同一云订阅在网页与受支持的桌面端共享权益和用量，不重复收费。
- 云备份指 **Nodal 项目元数据及知识内容**，不包含业务数据库本体、行数据或数据库灾备。
- 首期不做浏览器直连数据库、云端 SQL 执行、数据库写入或实时共编。
- 现有 Community、自托管和 MIT 授权代码不因官方托管订阅而被追溯收回或锁定。
- 不能把既有本地历史改称“高级版本历史”后移入订阅，也不能对已承诺的未来权益重新收费。P0 形成既有权益清单。

## 3. 为什么需要 Cloud：与 Git 工作流的分工

Git 工作区已经免费提供版本化、可审阅、可团队共享的数据库知识，历史不限时长。如果 Cloud 只卖“同步 + 备份 + 历史”，对会用 Git 的工程师几乎没有吸引力。因此 Cloud 的价值必须落在 Git 做不到或做起来很重的地方：

| 需求 | Git 工作区（免费） | Nodal Cloud |
| --- | --- | --- |
| 工程师之间共享、审阅知识 | 适合：PR 审阅、无限历史 | 不与之竞争；可从桌面一键发布到云 |
| 产品、分析、测试、新成员浏览结构与业务含义 | 需要克隆仓库并安装桌面端 | **浏览器打开链接即可浏览、搜索** |
| 非工程角色反馈“这个字段什么意思” | 需要 Git 账号与 PR 流程 | **对象上直接评论**，作者在桌面/网页处理 |
| 使用 AI 解释结构、找表、写文档草稿 | 自配模型与密钥（BYOK） | **托管 AI**，无需自管密钥和供应商账号 |
| 多设备、无人维护的历史与备份 | 需自己管理仓库与远端 | 自动保存与恢复（支撑能力，不作为主卖点） |

产品原则：

- 工程师继续以 Git 为主也是合理用法，Cloud 不应劝阻或干扰。
- 首发营销与引导围绕“分享 → 评论 → 询问 AI”展开，同步与备份作为随附能力。
- 以上是待验证的假设（§7 H1–H3），不是已证实的需求。

当前分发渠道：GitHub Community（Universal DMG，含 Developer ID 签名公证版本；Windows NSIS 安装包；自行编译）、Mac App Store 付费 Pro，以及计划中的网页在线版。

| 能力 | Community macOS（DMG） | Community Windows | MAS Pro | 网页在线版 | 自行编译 |
| --- | --- | --- | --- | --- | --- |
| 本地功能 | 按 Community 能力集 | 同左 | 按已购买 Pro | 不适用 | 按源码 |
| 连接自托管云 API | 保留 | 保留 | 当前不可用，本方案不开放 | 不适用 | 保留 |
| 登录官方云、免费账号能力 | P1 开放 | P1 开放 | P2 起逐项开放 | P1 开放 | 可登录，不提供专门支持 |
| 购买 Nodal Cloud | 跳转网页收款 | 跳转网页收款 | **仅 StoreKit IAP**，应用内不放网页购买链接 | 网页收款 | 网页收款 |
| 使用其他渠道已购订阅 | 是 | 是 | 是，前提是同一权益也以 IAP 提供 | 是 | 是 |
| 托管 AI | 有订阅时可用 | 同左 | 同左 | 同左 | 同左 |
| 应用更新 | GitHub updater | GitHub updater | 仅 App Store，updater 继续隔离 | 不适用 | 自理 |

矩阵规则：

- 官方 API 只按账号权益和协议版本判断，不信任客户端自报的渠道或 UI 开关；开源客户端调用官方 API 不构成绕过。
- 渠道只决定“在哪里付款、如何管理订阅”，不决定订阅后能用哪些云能力。
- MAS 内的购买引导遵循 Apple §3.1.1 / §3.1.3(b)：默认只走 IAP，不内置外部购买导流；上线前重新核对适用条款与地区差异。
- Windows 与 Community 是否在 P1 就开放官方云登录列为待决策 D2（§14），本文建议开放：用户基数最大，免费账号成本低，是主要获客入口。

## 6. 套餐与定价假设

以下是 P0 验证用的起点，不是正式定价。现有 US$0.99 活动价属于桌面买断，与订阅无关。

| 套餐 | 建议价格（USD） | 范围 |
| --- | --- | --- |
| 免费账号 | $0 | 接受分享、浏览、评论；自建 1 个云项目，30 天在线历史；外链数量与访问频率受限；无托管 AI |
| Nodal Cloud（首发唯一付费档） | 验证区间 $5.99–9.99/月，起点 $7.99 | 不限常规项目数（滥用保护上限 50）、365 天在线历史、在线编辑、分享与评论、归档、托管 AI 每月 300 单位起 |
| 试用 | 14 天 | Nodal Cloud 全部能力；托管 AI 试用上限 50 单位以控制成本 |
| Team | P3 再定 | 编辑席位、项目权限、复核、团队 AI 池；见 §12 |

调整说明：

- **免费账号** 是“分享给非工程角色”这条主线的必要入口：被分享者不应被要求付费才能看和评论。
- **只卖一档**：首发不存在套餐间升降级，额度换算与渠道生效时点规则大幅减少（技术设计 §8）。第二档（如更高 AI 额度）在有真实用量分布后再加。
- **不以存储容量分档**：元数据体积很小，GiB 配额没有区分度。容量只作为滥用保护的技术硬上限，达到上限冻结新增、不删除既有数据。
- 首发只做月付；年付、充值包、自动超额扣费均后置。

上线价格门槛（沿用 r1 并补充渠道费用）：

- 每账户贡献毛利 = 实际净收入（扣除 Apple 15%/30% 或网页收款费、税费、退款）− 模型成本 − 存储/流量 − 分摊基础设施与支持。
- 按“额度全部用完”的用户测算，而不只用平均值；含试用用户的 AI 成本。
- 内部目标贡献毛利 ≥ 60%；达不到则调整价格、额度或模型路由，不暗中削减当期已售权益。

## 7. P0：需求验证与 go/no-go

r1 只设置了成本门槛。r2 要求 P0 先回答“有没有人愿意为这件事付费”，再决定是否投入 P1。

待验证假设：

- **H1**：现有用户中，把数据库知识分享给不用 Git/桌面的角色是反复出现的痛点。
- **H2**：托管 AI（无需自配密钥）对相当一部分用户有付费意愿。
- **H3**：纯网页用户靠 DDL 导入与更新能完成有意义的工作，并愿意持续使用。
- **H4**：在 §6 价格区间内，满额用户的贡献毛利能达到目标。

验证方式（均为用户主动参与，不新增遥测）：

1. 访谈 10–15 名现有用户，覆盖 GitHub Community 与 MAS 用户，至少包含 3 名非工程角色。
2. 在官网与应用“云工作区”入口放置**如实说明尚未上线**的候补名单，可选填使用场景与可接受价格；不做伪装成可购买的假入口。
3. 用真实标准任务与长上下文任务测量托管 AI 单位成本，作为 H4 输入。
4. Spike：Tauri 下的 StoreKit 2 订阅 Swift 桥接可行性（约 2 人日），作为工期输入。

建议决策阈值（P0 结束时由产品负责人确认，可按实际调整）：

| 结果 | 条件（建议） | 后续 |
| --- | --- | --- |
| Go | H1 或 H2 在访谈中有 ≥ 40% 受访者描述为反复出现的需求；候补名单 ≥ 100 人且 ≥ 20 人认可价格区间；H4 测算达标 | 按 §13 进入 P1 |
| 窄 Go | 只有 H1 成立 | 只做免费账号 + 分享评论（P1），暂不做付费与托管 AI，复测 H2 |
| No-go | H1、H2 都不成立 | 不建设官方云；继续 Git 工作流 + BYOK，投入桌面 Pro 模块 |

P0 其他交付物：既有权益清单、外发字段白名单、渠道矩阵确认（§5）、成本模型、P1–P2 任务拆分与重估。

## 8. 用户流程与在线版范围

### 8.1 已有桌面用户

继续免 Nodal 账号使用本地功能。主动进入“云工作区”后登录（系统浏览器 + PKCE），选择要发布的项目与范围，查看外发预览后确认。默认不全量上传已有模型。

第二台设备登录后下载项目元数据，保留对象身份。数据库密码、SSH 密钥、SQLite 路径和系统授权不随同步迁移，重连数据源时在该设备配置。离线时照常本地工作，恢复网络后显示待同步与冲突状态。

### 8.2 分享与评论（首发主线）

1. 项目所有者在桌面或网页选择项目，分享给指定邮箱，或生成只读外链（默认 7 天有效，可撤销）。
2. 受邀者用邮箱验证码登录免费账号，浏览固定修订或最新版本。
3. 受邀者在表、字段、关系上评论；所有者在桌面或网页看到并回复、标记处理。
4. 评论不改变知识确认状态；只读外链不能评论、不能调用 AI。

### 8.3 仅使用浏览器的用户

无需安装桌面端即可注册。首个项目三种入口：示例项目、导入可携带 Nodal 归档、导入 PostgreSQL/MySQL DDL。

- DDL 在浏览器解析，展示覆盖缺口和将保存的元数据，确认后才创建云项目；默认不上传原始 SQL 文件。导入的结构标记文件来源与导入时间，不伪装成实时采集。
- **更新现有来源**：选择来源 → 解析并预览差异与覆盖缺口 → 确认对象映射及重命名候选 → 创建新结构基线。保留未受影响的注释和关系，受影响的知识标记待复核；未出现的对象默认视为未知而非删除，只有明确完整范围并经用户确认才提交删除；重复导入相同内容不产生新修订。
- 在线版首期不连接数据库、不执行 SQL、不访问本机 Git 与 Keychain。AI 生成 SQL 文本与执行分离。持续采集（客户侧 Connector）后置到 P4，并单独评审。

在线版目标能力：项目列表、结构浏览与图形、保存视图；注释、业务域、逻辑关系的持久编辑；历史查看、比较、恢复为新版本；分享与评论；托管 AI 找表、解释、差异说明与文档草稿；完整归档下载。

## 10. 托管 AI 产品规则

- 有界任务：结构解释、业务找表、关系说明、变更影响、文档草稿、SQL 文本草稿。沿用桌面“请求预览 → 明确发送 → 生成草稿 → 人工确认”流程，不自动执行 SQL、不自动确认知识。
- 用户确认的就是实际发送的内容；预览后项目或策略变化，需重新预览确认。
- “单位”是套餐内服务计量，不是现金或可交易货币；首期不出售充值。标准任务 1 单位起、高成本任务 5 单位起，按真实成本校准。
- 发送前显示预计/最高消耗与剩余额度；超出最高消耗须重新确认，不自动换更贵的模型。
- 按计费周期发放，不结转，提前展示重置时间。平台失败或未产生可用结果不扣用户额度。
- 额度用完后仍可查看已生成内容，可继续使用本地功能与 BYOK。
- 首期只开放少量经验证的模型路由，公开数据接收方、区域与留存政策；未核实前不承诺零留存或不用于训练。

## 11. 到期、降级与退出

- 到期后 30 天只读与导出窗口：停止云写入、托管 AI 和新分享；立即停用匿名外链；已有内容可查看、可下载完整归档。第 1、15、27 天提醒。之后进入清理，不承诺免费无限托管。
- 到期回落为免费账号能力：保留账号，超出免费额度的项目冻结为只读直至清理，用户可选择保留其中 1 个继续编辑。
- 完整归档无需有效订阅即可下载，可用免费 Community 桌面端离线打开和重新导入（技术设计 §10），取回不依赖重新购买。
- 本地已有内容持续可用，同步停止不删除桌面副本。恢复订阅后先核对版本再提交，离线修改不直接覆盖云端。内容已按公开期限清除时如实说明无法恢复。
- 账号删除必须可在应用内完成；删除不等于取消 Apple 订阅，流程中提示并提供订阅管理入口。

## 12. Team（P3，后置）

Team 在个人付费闭环验证后再立项，届时单独产出 Team 设计文档。r1 已形成、r2 保留的决定：

- 角色 Owner / Admin / Editor（付费席位）/ Commenter（免费）/ Viewer（免费），项目 ACL 可缩小权限；普通成员不自动读取全部项目。
- 免费成员不能修改知识、批准或调用 AI；需要双人复核时作者不能批准自己的变更。
- 首期固定 3/5/10 席位档位；超出席位时由管理员选择降为只读的成员。进入 MAS 前须有对应 IAP 产品并通过审核。
- 个人与团队订阅分开归属，加入团队不转移个人项目或占用个人额度。
- 最后一位 Owner 删除账号时须有无需接任人的完成路径（组织认领流程），不因此误删仍在付费的团队资产。
- 技术侧需要的授权代次、在途撤权检查点、团队额度池等机制，见技术设计 §13。

## 13. 分期与验收门槛

工作量为单个熟悉仓库工程师的粗估，不含 Apple 审核、支付开户和供应商等待；P0 拆分任务后再次修订。

| 阶段 | 预计工作量 | 可演示交付 | 必须通过的验收 |
| --- | --- | --- | --- |
| P0：验证与契约 | 5–8 人日 | §7 验证结果与 go/no-go、权益清单、字段白名单、渠道矩阵、成本模型、StoreKit spike、任务拆分 | 产品负责人签署 go/no-go；买断无回退 |
| P1：云工作区 Beta（免费） | 35–50 人日 | 邮箱登录、桌面 PKCE 登录、追加式修订、桌面发布与拉取、网页 DDL 导入与更新、在线编辑、分享与评论、完整归档、密钥粉碎删除 | 跨租户隔离；提交冲突不丢修改；删除后灾备恢复不复活；撤销分享后新请求被拒；无订阅归档可在 Community 桌面打开；不收费 |
| P2：托管 AI 与付费上线 | 35–50 人日 | 网页收款 + MAS IAP、试用、权益服务、托管 AI 与额度、成本硬上限、到期取回流程、MAS 云命令放行 | 真实交易（含退款、宽限、乱序通知）；重复请求不重复扣额；反复取消不突破成本上限；签名 MAS 包端到端；完成停服恢复与对账演练 |
| P3：Team | 30–45 人日，P2 后重估 | 邀请/席位、项目权限、复核、团队 AI 池、组织认领 | 在途撤权；个人/团队计费隔离；免费成员权限边界 |
| P4：扩展 | 另行估算 | 第二付费档、年付、对象级自动合并、实时通知、SSO、客户侧 Connector | 按付费用户需求立项 |

P0 → P1 → P2 构成个人付费闭环，约 75–110 人日。P2 完成后才正式销售；P1 的 Beta 用于继续验证 H1/H3。不将 Team 或实时共编作为当期已交付能力宣传。

核心验收场景（完整清单与技术细节见技术设计 §14）：

1. 老买断用户离线、未注册、订阅到期及云故障时，本地功能照常可用。
2. 两端修改同一项目、断网重连、提交成功但响应丢失，均不静默丢失修改。
3. 撤销分享或登出后，旧会话、外链和下载不能获得新数据；已下载副本的限制如实说明。
4. 删除项目后从灾备恢复，已删除内容不可读，已撤销的分享不复活。
5. AI 并发、取消、超时、供应商失败与重试，账本与用户可见扣费一致。
6. 应用购买与订阅分离；跨渠道重复购买提醒、退款、恢复购买都有明确结果。
7. 无桌面且订阅已过期的用户能下载完整归档，并在免费桌面端打开和重新导入。
8. 第二次导入 DDL 更新同一来源保留注释；部分解析不误删。
9. 使用合成 1,000 表、20,000 字段模型做发布、拉取与在线操作容量基线。

运营指标：首项目发布成功率、分享被打开率、评论数、第二设备打开成功率、冲突率、试用转化与流失、每账户成本与 AI 毛利；异常监控覆盖数据隔离、重复扣费、备份失败与供应商成本突增。
