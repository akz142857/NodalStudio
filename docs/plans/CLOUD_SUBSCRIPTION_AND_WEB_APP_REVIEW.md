# 云订阅与在线版：评审记录

日期：2026-11-07  
对象：[云订阅与在线版方案](CLOUD_SUBSCRIPTION_AND_WEB_APP_PLAN.md) 与 [云服务技术设计](CLOUD_TECHNICAL_DESIGN.md)。  
轮次：r0 → r1（多角色正确性评审），r1 → r2（范围与投入评审）。  
范围：设计评审与文档修订；没有修改产品代码、运行支付交易或验证生产环境。所有问题只能标记为“设计已处理，工程待验证”。

## 1. 结论摘要

| 轮次 | 评审视角 | 发现 | 结果 |
| --- | --- | --- | --- |
| r1 | 产品与商业化、架构与数据可靠性、支付与安全隐私 | 12 项：P0 0，P1 6，P2 6 | 补入设计约束与验收门槛 |
| r2 | 范围与投入（是否值得做、先做什么、做多重） | 7 项：P0 2，P1 3，P2 2 | 增加 go/no-go 门槛与渠道矩阵；收窄首发；拆分文档；r1 的 12 项按最小正确机制重新处理 |

r1 的三个角色都在找正确性漏洞，修订结果是方案越来越严密，但没有任何一项质疑商业前提或投入产出。r2 补上这一视角。

保留的方向：桌面买断与可选订阅分离、元数据备份不冒充数据库灾备、网页独立使用、先异步协作、延续开源/自托管许可。

## 4. 核对的实现证据

- `apps/cloud-api/src/lib.rs`：`sync_bundle` 在 `pg_advisory_xact_lock` 之前调用 `require_project_role`（R04）。
- `apps/cloud-api/migrations/0001_cloud.sql`：`project_bundles` 以 `project_id` 为主键，只存最新一条；`team_members.role` 仅 owner/editor/viewer。
- `apps/desktop/src-tauri/src/purchase.rs`：`unavailable_in_mas` 对所有含 `cloud` 的命令及同步/策略命令返回拒绝；非 MAS 构建不受限（R14）。
- `apps/frontend/src/platform/web-platform.ts`：`exportPortableBackup` / `importPortableBackup` 在网页端不可用。
- `crates/snapshot-store/src/lib.rs`：已有 `PortableModelBackup` 格式与导入安全校验，可作为云归档基础（R02）。
- `apps/desktop/src-tauri/src/table_understanding.rs`：预览与执行使用同一份服务端构建的请求体（R11）。
- [购买与版本方案](MAC_APP_STORE_PURCHASE_AND_EDITION_PLAN.md)：GitHub Release 含 Universal DMG 与 Windows 安装包，仓库为 public（R14、R19）。

## 5. 政策资料与边界

- 账号删除必须有可完成的应用内路径，不能因仍有订阅或无团队接任人而阻断。参见 [Apple 账号删除要求](https://developer.apple.com/support/offering-account-deletion-in-your-app/)。
- 升级、降级、同等级切换的生效时点不同。r2 首发单档套餐避开组内切换，引入第二档时须按 [Apple 订阅等级与生效规则](https://developer.apple.com/help/app-store-connect/reference/in-app-purchases-and-subscriptions/auto-renewable-subscription-information/) 重新设计。
- MAS 内默认只走 IAP、不放外部购买导流；Community 桌面端不经 App Store 分发，可跳转网页收款。上线前重新核对 [App Review Guidelines §3.1](https://developer.apple.com/app-store/review/guidelines/#subscriptions) 的地区差异。
- 月度服务额度不同于独立购买的点数；未来出售充值须单独核对产品类型。
- 未发现“买断 + 可选订阅”模式本身与已核对规则冲突，不代表必然通过审核。

## 6. 复核与后续门槛

- r2 由单一评审者在 r1 基础上完成，未重新运行多角色并行评审。r2 的简化（尤其 R03 密钥粉碎与日志回放、R10 整包 CAS）改变了 r1 已复核过的机制，**建议进入 P1 前由架构与安全角色再复核一次**。
- 价格、额度、免费账号范围、托管地区、Web 收款商仍是产品决策（方案 §14），不因本次评审默认批准。
