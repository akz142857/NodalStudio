# Nodal Studio Code View 开发计划

2026-11-26 · AI 产物审阅方案

## 1. 产品定位

Code View 是本地 AI 产物审阅工作区。外部 AI 工具生成或修改源码、SQL 查询和 SQL 模型定义后，用户可以在 Nodal Studio 看到改动清单、查看前后差异、阅读完整上下文，并记录需要修改的地方。

界面借鉴 VS Code 的文件树、标签页和差异视图，使用 Nodal Studio 的设计系统。Code View 的源码操作以只读浏览、对比、查找和复制为主。SQL 查询验证使用现有 Query，数据库结构和本体变更使用现有 Review changes。各入口显示证据来自项目文件、数据库快照还是本体版本。

首版的验收任务是审阅同一个需求下的应用代码和 SQL 模型改动。例如 AI 修改订单报表的服务代码和 SQL，将统计口径从下单时间改为支付时间。用户可以从改动清单打开两个文件，核对过滤条件、关联键和时间范围，并记下需要修改的文件和原因。

## 2. 首版审阅流程

1. **选择项目与比较基准。** 从 Code 打开本地目录。Git 工作树默认将打开时的 `HEAD` 提交与当前工作树比较，显示基准提交和目标。首次无提交时展示现有文件，说明前一版本缺失。普通目录支持只读浏览。
2. **先看改动清单。** 有对比结果时默认显示改动文件，提供完整目录树供用户查找上下文。变更清单覆盖暂存、未暂存和未跟踪的文件，区分新增、修改、删除与可确认的重命名。仅暂存区存在差异时明确标出，可打开该版本。列表使用项目相对路径区分同名文件。
3. **查看变化与完整文件。** 用只读差异视图显示增删内容，支持上一处/下一处改动、文件内查找和行号。可切到完整文件阅读上下文，窄窗口可用行内差异。Git 基准与目标分别标明。打开 Go、Java、PHP、Python、Rust 和 SQL 文件时使用对应语言高亮，未知文本格式按纯文本显示。二进制、无权限、超限和无法识别的编码有明确状态。
4. **记录审阅意见。** 每个文件可以标为「已阅」或「需修改」，并可填写一条本地备注。已阅表示用户看过该版本。标记绑定文件的前后版本，差异变化后提示重新审阅，并保留旧备注。打开 Code 或手动刷新时核对最新工作树状态。
5. **切到对应视图复核。** SQL 模型文件直接查看定义和差异。用户需要验证查询结果时，可复制选中的 SQL；后续提供「在 Query 中打开为草稿」。已经有对应的数据库快照或本体版本时，从现有 Review changes 核对结构或业务定义的变化。

Git 默认列表描述的是基准到目标的全部改动，包括进入 Code 之前已经存在的修改。只有来源有明确证据时，才标明某个 AI 工具或会话。后续可让用户在 AI 开始前手动记录当前工作树作为基准，复核同一次任务产生的差异。

## 4. 数据和执行边界

- Code 从桌面导航独立进入，文件查看和比较可在离线、无数据库连接时完成。文件读取使用原生层签发的目录会话和相对路径，拒绝越界、符号链接和 Windows 联接。比较只读取项目文件和版本信息。文件内容和本地审阅记录默认留在本机。
- 审阅记录关联项目、文件路径和前后版本摘要，保存标记、备注及时间。目标发生变化时，旧标记仍指向原来的版本。列表、差异和标记校验使用同一文件版本，读取期间发现变化时提示刷新。项目切换后忽略上一项目的异步结果。
- 源码、SQL 查询和 SQL 模型定义都按照待审阅产物展示。执行 SQL 需在 Query 中由用户主动发起。数据库结构差异以实际可比较的快照为依据，本体差异以对应版本为依据。源码中的 `CREATE` 或 `ALTER` 只展示文本。迁移影响分析、自动 ORM 关联、代码编辑、提交和推送均从计划移除。
- 当前 Code 原型依赖 MySQL 快照和 SQL 引用索引。实施时复用现有导航及文件访问基础，将项目审阅入口从数据库上下文中解耦。逐项核对原型的相关代码、项目 SQL 写入和扫描入口，再撤下相应调用。旧项目绑定和代码血缘数据的兼容性随原型替换核对。 [当前 Code 入口](../../apps/frontend/src/App.tsx) · [原型页面](../../apps/frontend/src/components/code-view/CodeViewWorkspace.tsx)

## 5. 交付顺序和验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 1. 本地只读审阅 | 改动清单、目录树、多语言源码和差异、文件级已阅及备注 | 断网、无数据库连接时，审阅混合语言项目中的源码和 SQL 模型。覆盖新增、修改、删除、暂存、未跟踪，以及同名文件。刷新后重新修改过的条目回到待复核，原备注可查。单独验证普通目录、异常文件以及桌面各发行版本的文件访问 |
| 2. 审阅一轮 AI 改动 | 评估记录任务开始前的工作树基准、选择已有本地提交作为基准，以及复制审阅反馈。按实际需求加入项目搜索 | 工作树里已有用户修改时，可用选定的明确基准核对这一轮差异。复制的反馈包含文件路径、可用的行号和用户备注，可交回给外部 AI |
| 3. 衔接 SQL 和模型复核 | 将选中的 SQL 打开为 Query 草稿，按已知来源导航到数据库或本体复核 | 对同一业务需求分别查阅代码改动、SQL 模型定义与对应的结构或本体证据。查询执行及审阅结论分别由用户确认 |

首版本地审阅已在桌面开发版接入。重命名识别覆盖 Git 暂存区可以确认的改动。后续阶段继续验证单次 AI 任务基准，以及 SQL 草稿、数据库结构与本体复核的交接。
