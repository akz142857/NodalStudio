# Mac App Store 页面与功能送审检查

检查日期：2026-10-25。对象：当前工作区 0.2.4，包含未提交的购买授权与 P0 改动。

**结论：目前不建议直接送审。** 核心数据库理解、ER 图、只读 SQL、本轮变化复核的产品定位没有发现天然不适合 Mac App Store 的问题；主要缺口集中在隐私、云账号生命周期、沙盒文件访问、外部工具依赖与真实购买验收。

本次检查覆盖前端主要入口、中英文文案、对应 Rust/Swift 实现、商店配置，以及本机独立验收应用可访问的设置页面。未逐一执行所有数据源场景；未验证 App Store Connect 当前填写内容，也没有完成 Apple 签名沙盒包的真实购买和跨 Mac 验收。普通 debug 应用能操作不代表 App Sandbox 中可用。本次仅新增审查记录，没有修改产品代码、提交或发布。

## 送审前应解决的发现

### A1 · P1：应用内缺少隐私政策入口（确认缺口）

- 证据：`apps/frontend/src/components/SettingsPage.tsx:530` 的隐私页只有开关、安全审计和凭据清理；`:576` 的关于页仅发行说明、许可证和第三方声明。生产前端未检索到隐私政策链接，本机隐私页观察一致。
- 影响：用户无法在应用内查阅数据处理政策。依据 Apple 审核指南 5.1.1(i)，政策还需填写在商店元数据中；商店侧是否已填本次未知。
- 建议：设置 → 隐私与安全提供稳定 HTTPS 政策入口。明确本地结构/查询历史存储、用户选择的 AI 服务、云账号与共享数据、保留/删除方式、联系渠道和诊断实际行为。不要笼统声明“完全不收集数据”。
- 验收：中英文入口可达；线上页面无需登录；政策与实际网络请求、App Privacy 填写一致。

### A2 · P1：可创建云账号，但没有账号删除流程（保留该功能时必须处理）

- 证据：`SettingsPage.tsx:499` 可创建账号与团队；`:523` 的断开连接仅清除本机凭据，退出项目仅清除本地配置。`apps/cloud-api/src/lib.rs:168` 存在 `/v1/auth/bootstrap`，未发现对应账号删除 API。
- 影响：虽然付费授权不使用独立账号，现有云协作仍创建了服务端账号。自托管、需要管理员 bootstrap secret 的场景应向审核解释，但不能把本地断开当作账号删除。
- 建议：若保留，提供应用内发起删除、身份确认和服务端数据处置流程，明确共享团队数据与法定保留例外；或经产品决策从首版 MAS 中完整移除该账号创建能力及相关承诺，不能只隐藏一个按钮。
- 验收：能从应用发起删除，后端账号及应删除的个人数据确实处理，失败可重试。参见 [Apple 账号删除要求](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion)。

### A3 · P1：外部文件路径尚未完成沙盒授权适配（确认设计缺口，具体失败范围待签名包验证）

- 证据：`SettingsPage.tsx:439` 备份、`:452` Git 目录、`:605` 设置导入导出仍输入路径；`apps/desktop/src-tauri/src/lib.rs:3072` 等直接读写传入路径。`connection_security.rs:367` 的证书/密钥选择最终只保存路径。`Entitlements.appstore.plist` 有 user-selected read-write，但未发现持久 security-scoped bookmark 实现。
- 影响：手工输入容器外路径不会授予沙盒访问权限；首次文件选择成功也不能证明应用重启后仍可访问。已有系统选择器的其他导出流程不因此全部判为失败。
- 建议：外部文件/目录使用系统选择器；需要跨启动复用的证书、密钥和目录增加持久授权及失效后重新授权流程。
- 验收：真实签名沙盒包测试首次选择、重启、移动文件、权限撤回、取消选择、导入与导出。参见 [macOS App Sandbox 文件访问](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox)。

### A4 · P1：购买/审核环境尚未形成真实验收闭环（发布门槛，不能判定已经失败）

- 证据：`crates/storekit-bridge/native/Purchase.swift:22` 接受 Sandbox 还要求布尔值 sandboxReceipt；`:55` 通过收据文件名等于 `sandboxReceipt` 得出这个值。
- 风险：这是 Apple 已验证交易之外的额外文件名条件。目前没有证据证明在 macOS Sandbox、TestFlight 与审核环境均成立；不得以单元测试中手工传入 true 证明真实分发可用。本次也未确认它在真实环境一定失败。
- 建议：用真实分发环境验证该条件，按 Apple 支持的交易环境和验证信息确定策略，不依赖未经证实的收据命名假设。不添加审核专用绕过。
- 验收：首次正版启动、成功恢复、取消恢复、断网退出再启动、跨设备拷贝、恢复服务异常以及审核环境均有实测证据。详见 `MAC_APP_STORE_PURCHASE_ACCEPTANCE.md`。原有模拟/负向测试不替代这些证据。

### A5 · P1：变化集 AI 发送告知弱于表级问答（高风险需统一）

- 证据：`InspectorPanel.tsx:262` 仍使用旧 `AiAssistant` 解释变化集；`AiAssistant.tsx:25` 直接调用 explainSchema，只有供应商标签和通用 metadata 文案；`lib.rs:4210` 在远程 provider 下直接发送问题与上下文。表级 `TableAiAssistant` 已有发送范围预览。
- 影响：当前确实需要用户点击，不能称为偷偷自动上传；但变化集入口没有表级流程同等清晰的接收方/发送范围告知。Apple 5.1.2(i) 对第三方 AI 数据共享要求明确告知和许可。
- 建议：统一发送前展示服务地址、上下文范围、注释和问题是否包含，并以明确“发送”动作确认。不要把“不自动读取并发送行数据”写成用户输入也绝不含敏感信息的保证。
- 验收：取消不发请求；目标/范围变化后重新确认；不包含凭据或自动采集的查询结果；变化集与表级流程一致。

## 功能完整性与文案问题

### A6 · P2：Git 合并工具和 SSH 必须在干净沙盒环境验证

- `lib.rs:2839` 等执行外部 git，`:2866` 查询 `nodalstudio-semantic-merge`；`:2893` 给出的是 Git driver 配置命令，不是安装该工具。当前商店配置未见随包携带这个合并工具的声明。
- 普通用户机器可能没有可用 Git/合并程序。Apple 2.4.5 的自包含与可选技术要求需要结合实际分发方式处理；不是所有系统进程调用都违规。
- SSH 使用系统 ssh、临时 Unix socket 和外部密钥路径。需验证沙盒下临时目录、密钥、known_hosts 与子进程权限，不能仅凭使用 ssh 就断言违规，也不能将 Unix socket 误认为 TCP 监听。
- 建议：明确首版功能范围；保留的工具必须有合法完整的分发/授权方式和可用实现，避免把付费核心能力留给用户安装开发工具解决。
- 验收：无 Xcode、无额外 CLI、全新用户的签名沙盒环境完成支持的连接及 Git 操作，失败提示准确。

### A7 · P2：关于页包含过期内容和开发占位说明

- `apps/frontend/src/i18n/messages/zh-CN.ts:650` 仍为“发行说明 · 0.1.0”，实际版本为 0.2.4。
- `:653` 第三方声明仍显示“发行构建必须包含……许可证文本”，不是实际许可证清单。本次未找到随包许可证生成/资源接入的完整证据。
- `:652` 声明 MIT 并引用随附许可证；需核对正式许可证原文与包内内容。MIT 本身允许收费，开源不自动导致商店拒审，不能为收费随意改写既有授权。
- 验收：中英文显示正确版本与本版说明；包内可读取准确的第三方 notices/必要许可证，无开发待办文案。涉及许可义务的缺失应在发行前完成。

### A8 · P2：隐私开关和外部能力状态与实现不完全一致

- `SettingsPage.tsx:534` 等提供匿名诊断、崩溃报告开关；当前检索主要找到设置保存/策略逻辑，未找到完整上传实现。不是发现隐蔽遥测，而是 UI 容易让用户以为已有该服务。
- `SettingsPage.tsx:632` 外部能力卡按通用更新设置显示状态，没有按发行渠道区分；本机 MAS 验收界面仍显示“更新检查 已启用”，而 GitHub 更新已被商店通道禁用。
- “完全离线”未充分解释自动 StoreKit 校验可能与 Apple 通信。购买验证不应被误描述成开发者遥测，也不能以说明为由削弱合法用户离线可用目标。
- 验收：未实现能力隐藏或准确标注；MAS 显示 App Store 更新渠道；离线开关说明与实际网络行为、授权离线策略一致。

## 提交材料与建议顺序

1. 先完成 A1、A2 的产品范围决定、A3、A5；同步清理 A7/A8。
2. 完成 A4/A6 的签名沙盒验收。当前有分发证书的迹象，但证书存在不代表 profile、商店记录、真实购买链路已就绪。
3. 准备审核说明与可重复示例：两版数据库结构、变化复核步骤、只读查询示例；若宣传云/远程 AI，提供审核可用资源和明确步骤，不能只让审核员自行购买第三方服务。
4. 核对 App Store Connect 的名称、截图、支持/隐私 URL、价格、年龄分级、数据收集声明和出口合规声明。本次未访问后台，不判断这些已填错或已完成。
5. 对最终产物清点 required-reason API、第三方 SDK 和 Privacy Manifest 要求。本次未找到 PrivacyInfo.xcprivacy，但不能仅凭缺文件就断言所有 macOS 应用违反要求；需要按实际 API/SDK 判断。

没有必要为审核引入 Three.js 或改写为 SwiftUI。先保证当前承诺的功能在商店分发环境可用，并让页面说明与真实行为一致。
