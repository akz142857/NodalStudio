## E3：真实模型与用户任务效果

用户授权使用当前登录的 Codex/ChatGPT 进行评测，并在 2026-10-19 明确确认“允许按清单发送并评测”。本机官方 CLI 已有 ChatGPT 登录。官方非交互模式支持复用现有认证；本轮使用它作为临时评测适配器，不新增生产提供方或修改用户的应用设置。[官方说明](https://learn.chatgpt.com/docs/non-interactive-mode)

已执行两个实际项目的 20 项任务：15 项单表/字段解释、2 项仅问题扩词、2 项范围内候选排序、1 项真实 FK 路径解释。涵盖记录粒度、状态歧义、无外键、唯一性、权限、业务公式与无法仅凭结构回答的行数据统计问题。原任务、批准的完整请求预览及发送清单保留在 2026-10-18 的私有目录。

实际发送 **20 次，成功返回 20 次，Desktop 结构与证据校验 20/20 通过**，无重试、无固定回答兜底。批量验收测试实际运行 1 项、0 失败、0 忽略，内部包含 20 题；不将其重复计作 20 个新增单测。批准预览与实际请求的 JSON 结构逐题相等，20 题均保留原始请求、原始回答、CLI 事件和应用校验结果。

执行器在每次发送前要求请求与已确认预览结构匹配。每题独立 Codex 会话、禁用工具/插件/子代理/网页搜索，只传软件生成的请求内容；不读取凭据文件，也不提供业务行。实际 Desktop 的准备、HTTP 和返回校验路径参与验收。CLI 事件中只有回答条目，没有工具执行。模型错误和格式/证据错误保留原样，禁止固定回答兜底。

| 任务 | 数量 | 本轮观察 |
|---|---:|---|
| 单表/字段解释 | 15 | 引用均通过应用校验；区分主键与业务唯一性、注释与实际行为；无行数据时不提供统计数字 |
| 仅问题扩词 | 2 | 实际请求没有数据库元数据；返回检索词及歧义，没有声称真实表存在 |
| 已允许候选排序 | 2 | 各四个预选候选中，支付记录、售后商品明细分别排首位；不新增候选，待确认关联保持限定 |
| 已知物理 FK 路径 | 1 | 字段映射、方向及约束行为与证据一致；不把会话存在等同执行过业务操作 |

逐题依据复核由 **Codex 对照已发送元数据**完成，本批未发现无依据的确定性结论；这不是业务负责人的独立准确率标注。例如，单表范围没有发送 FK 对端时，模型保持关联目标未知；在批准的双表路径范围内才解释具体映射。订单题主动指出表注释与状态字段注释的主/子订单歧义。Q15 的实际字段注释含状态编码，因此不能把它计作“完全没有枚举依据”的对抗样本；回答正确保留“已完成是否等同成功”的未知。

另以实际扩词结果重放前端本地检索，没有追加模型请求：Q16 支付记录的暂定目标保持第 5 位；Q17 到货明细的暂定目标从第 20 位提升至第 2 位。目标来自元数据判断，尚非业务负责人标注。两题均进入前五，但不证明稳定改善；排序题使用预选候选，也不能证明从全库自动召回后排序的端到端质量。

### 验收执行器 Review 的 P2 修复（2026-10-19）

多角色 review 确认本次 20 题证据完整、范围受控、结论与剩余项标注准确；另发现执行器复用非空目录会覆盖或混合不同批次的记录。模拟 CLI 成功退出但未生成本轮答案时，还可能读入旧答案。该风险未发生在已保存的 20 题中。

已修复 [验收执行器](../Scripts/run_ai_model_acceptance.py)：

- 在认证检查、启动服务及模型调用之前拒绝非空输出目录；隐藏文件、子目录及失败运行的记录同样阻止复用。已有文件不被删除或覆盖。空目录使用排他创建的 `.run-started` 标记，防止两个执行器同时占用。
- 每题的请求和事件日志排他创建，答案路径已存在时拒绝调用。只接受单个会话、单个成功完成的 turn，以及其中唯一的非空回答；答案文件必须与本次 `agent_message` 一致，仅忽略两端空白。缺文件、空回答、事件缺失/不一致、失败事件、工具执行或 CLI 非零退出均不能记作成功。
- 批量结束时核对实际交换数量及成功状态，原有批准请求体匹配和应用结构/证据校验继续生效。

[22 项 Python 离线回归](../Scripts/tests/test_run_ai_model_acceptance.py)全部通过，覆盖成功/失败后重跑、隐藏文件/子目录、并发占用、答案路径冲突、空回答、缺少最终事件、答案不一致、失败/超时和未批准请求；正常回答与空目录保留正向对照。测试使用合成文本，CLI、Cargo 和 HTTP 服务边界均以替身控制，不触发模型、数据库或网络访问。已加入 CI 的 `acceptance-runner` job；修复当时尚未推送，后续交付验证与历史验收分开记录。

```sh
python3 -B -m unittest discover -s Scripts/tests -v
```

新校验器只读核验已有 20 组事件/回答全部通过。对原始目录直接执行启动检查，确认非空目录立即拒绝；修复前后两个私有证据目录共 **81 个文件 SHA-256 全部相同**。本轮没有追加模型调用，没有改写原始 20 题汇总或答案。修复验证记录单独保存于 `target/ai-acceptance/2026-10-19/runner-fix/validation.json`。

| 步骤 | 必须观察到的结果 |
|---|---|
| A 确认说明，导出/推送；B 首次接收 | B 原文可见且待复核；AI 上下文与本地业务召回不使用它 |
| B 本机重新确认，同文再次接收 | B 原确认仍有效；确认 ID 不被发送端替换 |
| A 的相关约束删除、重新采集并发送，B 持有相同新快照 | B 待复核；全局指纹一致不能恢复旧确认 |
| B 待复核，同文再次接收 | 继续待复核 |
| B 修改并确认文本后传回 A | A 接收新文但不能沿用旧文确认；重新确认后才恢复复用 |
| 切换来源/断网重试/恢复应用 | 旧回答、旧草稿不能覆盖当前任务；已提交写入最终状态可重读 |
