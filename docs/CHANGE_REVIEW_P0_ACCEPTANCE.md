# P0 本轮变化复核：实施与验收记录

日期：2026-10-24 / 25（Asia/Singapore）。验收对象为当前工作区源码构建的独立 macOS 调试应用，不是正式发行版。

## 已实现的闭环

- 桌面“变更”默认进入本轮复核；历史任意版本比较独立保留。工具栏和单表理解面板可进入工作区。
- 每个本机来源有独立起点、活动轮次、目标、采集收据和事件记录。建立起点不自动确认旧说明。
- 分开展示结构变化与理解影响，覆盖说明、逻辑关系、原始业务域成员及保存视图根表。
- 保留或修订说明后显式确认；暂缓必须填写理由，始终阻塞完成；归档保留原文/依据，排除当前复用；无效关系可停用；缺失视图引用须明确接受限制。
- 提交前展示预览；事务内校验完整证据 revision、10 分钟有效期和操作 ID。重复请求幂等，冲突保留当前编辑草稿。
- 确认沿用原来的表、关系和说明依赖，不能通过重新确认默默缩小依据。缺失依赖拒绝确认。
- 只有全部事项处理后才允许完成，并原子推进基线。相同指纹刷新不生成重复结构待办；刷新失败保留模型并阻止完成。
- 事件、基线、说明与同步队列在本机事务中提交；数据库结构没有新增写入接口。工作流无需 AI。
- 本机库版本升至 6；升级保留旧库备份，历史裁剪保护基线和确认依据，来源删除/重置清理新增记录。

## 实际技术落点

`crates/snapshot-store/src/change_review.rs` 负责投影、事务和生命周期；复用现有知识确认规则。桌面注册 `get_change_review` / `apply_change_review` 两个命令；前端以 sourceId 隔离会话。

与最初方案的实现取舍：

- 使用两条命令与统一 action 请求，替代七条单独 IPC；提交时的校验与原子性不变。
- 影响投影在一致性 SQLite 事务中重算，revision 覆盖快照、身份、全部相关语义、收据和事件，不依赖各入口维护脏标记。
- 归档将当前 description 清空，保留标签/负责人，并将原文与依据保存在事件中；因此现有 AI、导出、共享消费者不会继续输出归档说明。初版仅能取回原文手工编辑；现已补齐一键恢复并强制重新复核，见[补齐验收](CHANGE_REVIEW_P0_EXTENSION_ACCEPTANCE.md)。
- 初版采用逐项已阅与前端展开；现已补齐后端分页及批量已阅，见[补齐验收](CHANGE_REVIEW_P0_EXTENSION_ACCEPTANCE.md)。复杂表级分组仍未实现。
- 收据只声明成功/失败及观测范围。权限不透明时显示“未观测到”，不能将缺失对象证明为删除；不是全库权限完整性证明。
- 原有本机确认和本轮完成记录不进入可移植的共享确认资格。暂缓和理由跨重启保存；未提交文本及搜索筛选尚不跨应用重启保存。

## 性能测量边界

本机 Rust debug + 内存 SQLite，每组 10 次投影，按 nearest-rank 记录 p95：

| 合成目录 | 结构事项 | 投影 p95 |
|---|---:|---:|
| 500 表，每表 4 字段变化 | 2,000 | 223 ms |
| 2,000 表，每表 4 字段变化 | 8,000 | 910 ms |

测试确保全部事项保留且不会自动完成。此数据不包含 IPC、WKWebView 首屏、交互延迟或高密度说明依赖，不能替代原方案中的原生 p95 指标。后续补齐已将 IPC 响应改为有界分页；完整影响计算与事件重放仍是大型项目后续优化点。

## 原生验收环境与步骤

- 独立标识：`com.claycosmos.nodalstudio.change-review-p0`；构建位于 `target/debug/bundle/macos/Nodal Studio Change Review.app`。
- 独立数据目录；没有替换 `/Applications/Nodal Studio.app` 或访问其工作数据库。
- 临时 Compose 项目 `nodal-review-p0`，PostgreSQL 17 / MySQL 8.4；使用仓库元数据 fixture。外部测试命令增加 `orders.review_note`，应用只读刷新。
- `apps/desktop/src-tauri/examples/change_review_fixture.rs` 提供显式 opt-in 的基线构造；仅接受含 `change-review` 的路径。初始确认由 fixture 建立，后续主流程通过原生 UI 操作。
- PostgreSQL：中文/浅色/125%，刷新 → 2 项待办 → 填写理由并暂缓 → 退出 → 重启 → 暂缓理由和旧基线仍在 → 修订确认 → 结构已阅 → 显式完成 → 基线推进到新目标。确认对话框经 Tab / Space 操作成功。
- 原生验证发现并修正入口按钮样式、内部标识暴露、无差异时工作区错误居中、完成后的空态文案问题。

- MySQL：原生刷新采集到新增字段 → 归档说明并填写理由 → 查看结构变化 → 完成本轮 → 处理记录展开原说明。两个来源基线互不影响。
- 英文/深色/125%：检查完整工作区和处理记录，原文与用户理由保持原语言。切换语言后的即时成功提示随界面语言更新。
- 最终构建再次启动：归档说明不再计入工具栏待办；英文深色/125% 下展开左右侧栏，完成状态、操作与长文本均可读，截图为 `native-final-dark-narrow.png`。宽区处理记录截图为 `native-final-history.png`。
- 原生数据落盘再核验：两个来源均 completed 且基线等于最新快照；PostgreSQL 保存修订说明，MySQL 当前说明已排除、事件仍有原文；两者标签与负责人均保留。见 `native-store-assertions.json`。

原生截图和 AX 记录位于同一验收目录。MySQL 首次刷新出现较长等待，最终完成并保存新快照；未把等待阶段判定为采集成功。该过程使用独立 fixture 凭据，未读取正式来源凭据。
