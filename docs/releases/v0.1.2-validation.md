## AI verification and remaining limitation

The existing provider configuration and original Keychain entry survived the upgrade. The installed 0.1.2 provider test connected successfully to `deepseek-flash` at the official DeepSeek endpoint at 10:52:52 Asia/Singapore. This test uses an empty metadata context.

Two additional native requests used a separate imported model containing seven synthetic tables, with no database connection or business rows:

- Order grain: prepare preview → explicit send → completed explanation, evidence links, unverified interpretations and outstanding questions.
- Unknown status/currency: completed explanation explicitly stated that the supplied metadata cannot determine whether status 2 means successful payment or identify the currency.

The temporary Keychain entry was created only after explicit user approval, used by the installed application, and deleted after testing. The original credential remained present. No generated interpretation was accepted into semantics. The synthetic model was exported for recovery and removed after testing. Native Remove connection returned `Operation failed`; cleanup therefore used a transaction restricted to the newly created synthetic source ID, restoring the original selected source. The transaction checked all original data/settings table digests before committing. This cleanup limitation is separate from AI and updater acceptance.
