# v0.1.3 release preparation — 2026-10-23

Status: source review, fixes and automated validation complete; distribution and native/model acceptance remain pending. Not published. Dates use Asia/Shanghai.

## Source and review

`git pull --ff-only` confirmed that `main` was current at `ad0a38e` before this work. The working tree was clean. The review covered the AI experience changes since `v0.1.2`, plus release and update reliability. Three parallel reviewers covered frontend/UX, Rust AI/privacy, and release/update behavior.

Six defects were fixed with regression coverage:

| Area | Defect | Result |
| --- | --- | --- |
| AI composer | Selecting the existing suggestion cancelled preparation without triggering another preparation | Every edit/suggestion attempt triggers local preparation |
| Knowledge confirmation | A refresh failure after a successful save appeared as a save failure and enabled another confirmation | Saved state is retained; refresh has a separate retry |
| AI cancellation | Removing a completed answer did not cancel an already borrowed task | Cancellation invalidates its token and is checked again after asynchronous revalidation |
| macOS packaging | An arbitrary old DMG could be selected from a reused output directory | Only a unique current-version DMG is accepted |
| Updater manifest | Tar end markers could hide a damaged gzip trailer | The remaining compressed stream is read and validated before manifest generation |
| Update selection | Build metadata participated in version ordering | Signed update checks use SemVer precedence and retain channel filtering |

The root, frontend, desktop, Tauri configuration, Rust workspace and local workspace entries in `Cargo.lock` are updated to `0.1.3`. Existing signing public key, update feed and database schema version are unchanged.

This establishes packaging/build success, not native interaction or universal distribution acceptance.
