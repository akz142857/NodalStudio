## P1：导入备份可把现有凭据关联到另一个数据库地址

代码路径：

- `crates/snapshot-store/src/lib.rs:1734`：导入仅清除 SQLite 文件绑定；网络 profile 的 host、port、username、TLS/SSH 配置直接覆盖同 ID 的现有 profile。
- `crates/snapshot-store/src/lib.rs:1749`：同时恢复备份中的来源设置，包括 `refresh.auto_connect`。
- `apps/desktop/src-tauri/src/lib.rs:3508`：桌面导入验证后仅清除 AI/Cloud 的“已配置”标志，没有把现有凭据与导入的新目标隔离。
- `apps/frontend/src/App.tsx:512`：启动时自动连接启用的来源；`apps/desktop/src-tauri/src/lib.rs:1298` 仍按原 source ID 从 Keychain 读取数据库密码，并交给新 profile 的连接地址。

触发条件：导入文件包含一个本机已有来源的 UUID（例如在该来源导出的备份上修改），改变网络目标并启用自动连接。当前导入预览没有显示新的主机和凭据复用关系。下次启动/连接会继续使用原 UUID 关联的数据库凭据；若目标是不可信服务，存在凭据泄露风险。该问题不要求备份内含有密码，但要求本机已有该来源的可用凭据。

隔离复现确认：现有 `original.invalid` profile 被替换为 `replacement.invalid`，source ID 不变，自动连接为 true；以“不得让导入的新目标自动复用已有凭据身份”为断言的测试失败。测试没有访问真实 Keychain 或连接服务器；凭据实际取用由上述调用路径确认，未声称完成真实密码外传实验。

修复要求：将模型内容恢复与本机连接身份分离；导入的新网络目标默认未绑定、禁用自动连接，必须经过明确的目标确认与凭据重新绑定/验证。仅清除 UI 标志或禁用启动自动连接不足以阻止之后的手动连接复用旧凭据。AI/Cloud endpoint 变更也应检查对应凭据绑定规则。

## P1：导入 B 来源可覆盖 A 来源的模型对象

代码位置：`crates/snapshot-store/src/lib.rs:1795`、`:1809`，以及关系导入的同类全局 ID upsert。

`validate_portable_backup` 只校验包内对象的 `source_id` 等于备份的来源，未检查这些对象 ID 是否已属于本机另一个来源。领域分组、保存视图、逻辑关系遇到全局 ID 冲突时，会把既有记录的 source_id 和内容一起改写。

触发条件：导入 B 的文件携带与 A 已有对象相同的 UUID。无需包内混用来源 ID，格式验证仍可通过。预览宣称不影响无关本地数据，但 A 的对象会消失并被归到 B，造成跨来源本地模型数据破坏。

隔离复现确认：内存数据库预先保存 A 的一个领域分组；导入 B 的合法来源设置和同 ID 分组后，导入成功，A 的分组数量由 1 变为 0。断言 A 的分组必须保留失败。

修复要求：在同一事务内验证所有全局 ID 的现有归属；跨来源冲突应整体拒绝，或完整重映射 ID 及引用。需要覆盖视图、分组、关系、快照、变更集及相关引用，不能只修复领域分组一处。

## P1：Git 工作区导出可沿符号链接覆盖仓库外文件

代码位置：`crates/git-workspace/src/lib.rs:245`、`:249`、`:771`；桌面入口 `apps/desktop/src-tauri/src/lib.rs:1698`。

`safe_join` 仅拒绝绝对路径和 `..` 等词法路径成分，不检查工作区根、父目录或目标文件是否为符号链接。`fs::write` 随后跟随符号链接并截断其目标。

触发条件：用户导出到一个包含被替换/不可信 `.nodalstudio` 文件的仓库。例如 `.nodalstudio/README.md` 为指向仓库外文件的符号链接。桌面只检查所选仓库的访问权限，未约束每个实际写入目标。开源 macOS 包可按当前用户权限覆盖仓库外文件；MAS 影响还受系统已有授权范围限制，不能假定系统沙箱补足该应用层边界。

隔离复现确认：在临时目录创建“所选仓库”和外部文本文件，把仓库 README 链接到外部文件后调用真实 `write_workspace`，导出返回成功，外部文本被覆盖为生成的 README。测试只操作专属临时目录，并在断言前清理。

修复要求：写入、读取及删除旧托管文件时都约束实际文件系统边界；拒绝符号链接/重解析点逃逸。检查必须覆盖根和全部父级，并考虑检查与写入之间的竞态；单纯字符串前缀或一次 canonicalize 检查不充分。

## 复现与验证边界

新增测试：

- `crates/snapshot-store/tests/review_import_boundaries.rs`：两条预期安全断言失败，分别证明连接重定向状态和跨来源覆盖。
- `crates/git-workspace/tests/review_symlink_boundary.rs`：Unix 上的仓库外文件保护断言失败。

执行命令：

```sh
cargo test -p snapshot-store --test review_import_boundaries --locked -- --nocapture
cargo test -p git-workspace --test review_symlink_boundary --locked -- --nocapture
```

本轮结果为 **3 条安全断言失败**，不是环境或依赖失败。原始日志保存在本机 `target/main-review-v1.1.0/import.log` 和 `target/main-review-v1.1.0/symlink.log`。测试使用内存 SQLite、虚构地址及隔离临时文件，没有读取用户业务库、真实凭据或覆盖用户文件。

审查另覆盖了 SQLite 只读打开/查询取消/文件授权生命周期、PG/MySQL 只读事务、StoreKit IPC 授权、更新归档校验/备份/回滚及 AI 发送前校验路径；本轮未在这些检查路径上确认新的 P0/P1。该范围说明不是“全部源码无漏洞”的保证，也不以此前全绿 CI 抵消本报告的新失败证据。

建议先修复并验证上述三项，再决定已公开版本的处置及补丁发布。不得覆盖已经发布的 v1.1.0 安装包来隐藏差异；需要发布时使用新的补丁版本和完整验收证据。

## Build 5 修复记录

用户随后要求修复全部 3 项 P1，并恢复 App Store 发布、生成 1.1.0 Build 5。已实现：

1. **凭据身份**：portable import 保留已有来源的本机连接配置；新来源清空网络地址、账户、端口和 TLS/SSH 文件配置，作为离线模型恢复。备份和设置导入均保留本机 AI/Cloud/Git 配置，关闭自动连接。采集与查询在读取 Keychain 前拒绝未绑定模型；连接测试、保存、验证刷新要求重新输入数据库密码，且不能回退到同 UUID 的旧数据库/SSH 凭据。SQLite 仍要求重新选择本机文件。
2. **来源归属**：portable import 在同一事务内预检所有全局对象 ID、来源归属和相关引用，跨来源冲突整体拒绝。范围包括分组、视图、关系、快照、变更集、provenance 和布局引用。共享分组/视图/关系保存方法也加入 SQL 归属条件，其他入口无法借同 ID 转移这些对象。
3. **Git 文件边界**：使用 `cap-std` / `cap-fs-ext` 的目录句柄逐级打开托管目录，拒绝根、父目录及叶子符号链接；读取、预览、写入、旧文件删除及 legacy 目录均走相同边界。写入使用同目录临时文件原子替换，避免截断外部硬链接目标。没有扩大沙箱权限。

新增 9 条回归测试：导入边界 4 条、真实 Unix 文件边界 4 条、离线凭据重新绑定 1 条；其中测试矩阵覆盖多个对象类型、根/父/叶链接、清单、旧文件删除和硬链接。原始三条失败场景均已转绿。完整验证与安装包身份另见 [Build 5 交付记录](v1.1.0-build5.md)。

本修复不修改已公开 GitHub v1.1.0 的标签或安装包，App Store 使用递增的 Build 5。Windows 的链接/重解析点运行时验收不能由本机 Unix 回归代替；其他系统的证据以对应 CI 为准。
