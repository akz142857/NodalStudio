# v0.2.1 validation and release record

Status: release preparation on 2026-10-24 (Asia/Singapore). Publication, final-source CI and distribution verification are pending.

## Scope

This patch enables startup checks for new settings, adds an actionable update banner and notification, and separates update discovery from workspace health checks so restoring a data source cannot discard the result. Existing saved opt-outs remain preserved. Failed settings reads do not trigger checks using fallback defaults. Download, signature verification, installation confirmation, backup and restart behavior is unchanged.

The production app identifier, updater public key and local database schema are unchanged. All four JSON package/configuration versions, the Cargo workspace and its 13 local lockfile entries are 0.2.1.

## Feature validation before packaging

- Frontend: 128 files / 827 tests passed; TypeScript and ESLint passed. The focused update flow passed 26 tests after the final test-style correction.
- Settings model: six tests passed, including default-on behavior, preserved saved opt-out and offline organization policy. Rust formatting passed.
- Native debug builds passed. An isolated preview containing the changed code and test version 0.1.2 automatically detected public v0.2.0. The banner opened Updates & About; Later dismissed it; the notification still opened the same page. No download or installation was triggered in this preview.
- A current local 0.2.0 build reopened the existing MySQL model with 499 tables and three views. Its startup check reported up to date at 16:22:19. Automatic checking was enabled through the installed app's UI and persisted. Local table digests changed only for application settings and the external-access audit log.
- Private preview configuration, screenshots and verification are retained under `target/update-notice-acceptance/`, ignored by Git. Preview evidence is separate from final signed-package acceptance.
