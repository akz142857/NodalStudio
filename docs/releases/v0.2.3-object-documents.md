# v0.2.3 — Central object documents macOS test rebuild

This rebuild keeps the user-selected version 0.2.3 and supersedes the earlier local test package for UI testing. It is not a new public release.

## Changes

- Functions, views/materialized views, procedures and triggers open in a central read-only document. The object tree stays stable; returning to the diagram preserves its mounted canvas and viewport.
- Definitions support syntax highlighting, line numbers, wrapping, copying and search. Properties and catalog-confirmed dependencies have separate sections. The optional right inspector follows the active object; table-trigger links use the same central document.
- Advanced update settings have consistent inset spacing and no browser-default fieldset border. Capability settings have grouped filters, clearer selection and improved detail spacing.
- Object-tree action buttons use centered shared SVG ellipsis icons.
- New settings and category resets default to 110% interface scale in both frontend and Rust. Existing saved scale preferences are retained.

## Validation and delivery boundary

Real desktop acceptance is recorded in `docs/LOCALIZATION_NATIVE_ACCEPTANCE.md`: PostgreSQL/MySQL objects, Chinese/English, 125% UI scale, an 800-line temporary function, dependency navigation and a pixel-identical sampled canvas before/after a document round trip. The temporary database function was removed after acceptance.

The document workspace is a single reusable preview. Pinned tabs and document navigation history are not included.

The macOS package uses the regular application identifier and data location. It is Developer ID signed, with notarization omitted as in the preceding local package. No automatic installation or public GitHub Release/updater publication is included.

Final pre-package validation: 138 frontend test files / 875 tests passed; all 6 `settings-model` Rust tests passed. Frontend lint and TypeScript checks passed. Existing native acceptance evidence is retained; the installer rebuild is verified separately below.
