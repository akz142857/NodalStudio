Nodal Studio — application updates and GitHub Releases

Scope
Manual check, signed full download, cancellation/retry, explicit install/restart,
local data backup and shared Settings design-system UI. macOS first.
Scheduled checks, staged rollout and migration recovery UI
remain later phases. The existing opt-in startup check is retained.

GitHub source (2026-10-22)
The official public repository is https://github.com/akz142857/NodalStudio.
Normal builds without an updater public key query its public Releases API and
offer a browser entry to the official release page for manual installation.
Windows uses this manual flow too; native installation remains macOS-only.
Stable checks use /releases/latest and reject prereleases. Beta checks select
the highest semantic version among the 100 most recent published releases,
including stable releases. Drafts and non-version tags are excluded. No token is
embedded or sent. Rate limits, unavailable releases and invalid responses are
reported as errors, never as an up-to-date result. Offline mode and organization
policy also block the release-page action.

A macOS distribution with an embedded updater key uses:
https://github.com/akz142857/NodalStudio/releases/latest/download/latest.json
The manifest points to immutable /releases/download/vVERSION/... archive URLs.
GitHub metadata alone never enables native download/install. Failed signed-feed
checks or signatures do not fall back to installing an unsigned release.
Custom feeds require a trusted key; clearing a custom feed restores the default.
The official signed endpoint is stable-only. Beta signed updates require a
dedicated custom feed (optionally containing {channel}); selecting Beta without
one reports that configuration requirement instead of reusing the stable feed.

At inspection time, GitHub v0.1.0 contained a macOS DMG, an unsigned Windows
installer and SHA-256 sidecars. It had no latest.json, .app.tar.gz or Tauri .sig.
Those existing attachments support manual installation, not in-app installation.
A checksum or Apple code signature does not replace the updater signature.

Trust and state
Rust owns the selected Update and its exact verified bytes. No install path, key,
version or bytes are accepted from the WebView. The official Tauri updater verifies
its signature. The signed archive must also contain the matching bundle identifier
and version, and its declared executable must be present, nonempty and executable.
Traversal, duplicate paths, multiple app roots, links, corrupt gzip trailers and
oversized expanded archives are rejected. Both download and expanded archive sizes
are limited to 512 MB. Transfers have a 30-minute total deadline and a 30-second
connection/read timeout; the short feed-check deadline does not truncate downloads.
HTTPS is required for both feed and downloads, including redirects.
The first version permits no symlinks in an update archive (current bundles have none).
Offline mode blocks check/download. Organization policy blocks all update operations.
No credentials or database contents are sent to the update feed.
A cancelled or interrupted download starts again on retry; resumable downloads are
not implemented. Verified bytes live only in process memory and must be downloaded
again after an ordinary quit.

Install safety
The shared frontend IPC bridge waits for running application operations and blocks
new ones during installation. Native checks additionally cover active queries,
captures, metadata synchronization and AI requests. Unsaved table knowledge,
AI/Cloud drafts, model relationship editing and temporary DDL previews block restart.
Query SQL drafts are persisted in local browser storage; query results are never
persisted there. If a draft cannot be saved locally, installation is blocked even
after leaving the query page. Factory reset clears the saved drafts. The install
confirmation asks the user to finish all other edits first.
Installation from /Volumes or an unwritable application parent is rejected. Free
space is checked for the application, temporary directory and data directory.
SQLite VACUUM INTO creates a consistent backup that includes committed WAL data;
PRAGMA quick_check validates it before application replacement. The previous app
is copied with ditto. Backups are retained in the app data directory under
update-backups/<old-version>-<unique-id>/ and are not automatically deleted in phase 1.
A replacement error attempts to restore the previous app and displays a retry or
manual recovery message. This does not implement automatic rollback after a new
version launches or after a database schema migration. Do not point an older app at
a database with a newer schema. The tested first-phase versions share schema v5.
On macOS, a helper waits for the old process to exit and opens the installed bundle
through LaunchServices, so the new application gets a normal visible window.

Local acceptance build (no real user data)
Run Scripts/build_update_smoke.sh with Rust 1.95+, Node 24 and pnpm on the PATH.
An optional first argument selects a NEW output directory. Existing output is never
overwritten. The script creates a temporary test key and builds versions 0.1.1 and
0.1.2 with bundle ID com.claycosmos.nodalstudio.updater-smoke.
It creates target/updater-smoke/installed/Nodal Studio Update Test.app (0.1.1)
and target/updater-smoke/serve/ containing the signed 0.1.2 upgrade.
Start the loopback server using the command printed by the script, launch the
installed test app, open Settings > Updates & About, and check/download/install.
Confirm the restarted app reports 0.1.2 and retains synthetic local data.
To test rejection first, replace serve/latest.json with serve/bad-signature.json;
restore it from serve/valid.json, recheck and retry.
Only the explicitly enabled updater-smoke-test feature AND a bundle ID ending in
.updater-smoke permit a loopback HTTP URL. A normal build never accepts HTTP.
Never distribute these acceptance apps or the test signing key.

Prepare a real GitHub distribution
1. Generate and securely back up a dedicated Tauri updater signing key. Keep the
   private key out of source control; only the public key is embedded in the app.
   Example: pnpm --filter @nodalstudio/desktop tauri signer generate -w /secure/path/nodalstudio.key
   Do not reuse the updater-smoke key. Do not replace an established production key:
   existing installations trust the public key embedded in their application.
2. Install the maintained minisign verifier (on macOS: brew install minisign).
   Set UPDATER_PUBLIC_KEY_PATH in config/macos-release.env to the .pub file.
   Optionally set UPDATER_NOTES_PATH to a release-notes text file.
   Set UPDATER_PRIVATE_KEY_PATH to an encrypted private key and
   UPDATER_KEYCHAIN_SERVICE / UPDATER_KEYCHAIN_ACCOUNT to its password entry.
   Alternatively export TAURI_SIGNING_PRIVATE_KEY (path or key content) and
   TAURI_SIGNING_PRIVATE_KEY_PASSWORD in the build environment. Never commit secrets.
3. Set the new stable version consistently in tauri.conf.json, the Cargo workspace
   and package metadata. Run pnpm release:macos. --check validates prerequisites.
   The script retains existing Apple signing/notarization/Gatekeeper checks, embeds
   the public key and GitHub endpoint through a temporary config, and generates
   updater artifacts. Never enable updater-smoke-test for distribution.
4. The script verifies the archive with minisign, checks bundle identifier/version,
   supported archive entries and actual Mach-O architectures, then prepares:
   dist/releases/macos-VERSION-updater/
     Nodal-Studio_VERSION_TARGET.dmg
     Nodal-Studio_VERSION_TARGET.app.tar.gz
     Nodal-Studio_VERSION_TARGET.app.tar.gz.sig
     latest.json
     SHA256SUMS
   Universal builds produce darwin-aarch64 and darwin-x86_64 entries pointing to the
   same signed archive. Single-architecture builds advertise only that architecture.
   The signature in latest.json is the .sig CONTENT, not a URL. Existing release
   output is never overwritten. No script uploads or publishes these files.
5. After reviewing the generated files, create a NEW draft GitHub Release with tag
   vVERSION and upload all five files. Keep generated filenames unchanged, verify
   the complete draft, then publish it as the latest stable release. Do not modify
   artifacts already installed by users. Every subsequent latest release must also
   carry a complete latest.json and the matching signed packages, or the /latest
   endpoint will stop working. Keep Windows test-only releases as prereleases.
6. Users of the old 0.1.0 app must install the first updater-enabled DMG manually.
   Test a signed old/new pair using the real GitHub feed before claiming production
   automatic-upgrade acceptance. Keep the earlier local acceptance record separate
   from validation against published production artifacts.

For existing signed artifacts or another build runner:
python3 Scripts/github_update.py configure --public-key /secure/path/nodalstudio.key.pub --output /tmp/updater.json
python3 Scripts/github_update.py manifest --archive /path/Nodal-Studio_VERSION_universal.app.tar.gz --signature /path/Nodal-Studio_VERSION_universal.app.tar.gz.sig --public-key /secure/path/nodalstudio.key.pub --version VERSION --target universal --output /path/latest.json
The configure subcommand without --output only validates the public key. Both
subcommands refuse to overwrite existing output. They do not need GitHub tokens.
